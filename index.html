01 Single Pointer T*
A single pointer (T*) stores the memory address of one object. It can point to a single object or the first element of a heap-allocated array. Dereferencing with * gives the value; -> accesses members of a pointed-to object.
single_pointer.cpp
#include <iostream>
using namespace std;

class Box {
public:
    int value;
    Box(int v) : value(v) { cout << "Box(" << v << ) created\n"; }
    ~Box()                { cout << "Box(" << value << ) destroyed\n"; }
};

int main() {
    // 1. Pointer to a single heap object
    Box* b = new Box(42);      // allocate
    cout << b->value << "\n";  // access member via ->
    cout << (*b).value << "\n";// same, using dereference *
    delete b;                   // free memory — always!
    b = nullptr;               // good habit: null out after delete

    // 2. Pointer to a heap-allocated array
    Box* arr = new Box[3]{1, 2, 3};
    for (int i = 0; i < 3; i++)
        cout << arr[i].value << " ";
    delete[] arr;              // use delete[] for arrays!

    // 3. Pointer to polymorphic object (most common in OOP)
    // Base* ptr = new Derived();  // covered in polymorphism
    return 0;
}
⚠ Common Mistakes
delete vs delete[]: use delete for single objects, delete[] for arrays. Mixing them is undefined behaviour.
After delete, the pointer is a "dangling pointer" — accessing it is UB. Always set to nullptr.
int* p; (uninitialized) is not the same as int* p = nullptr; — the first is a wild pointer.
02 Double Pointer T**
A double pointer (T**) is a pointer to a pointer. Used for: (1) dynamic arrays of pointers (e.g. Person** as an array of Person objects), (2) 2D dynamic arrays, (3) passing a pointer by pointer so you can modify the original pointer. In OOP, it's most common as a polymorphic array.
double_ptr_array.cpp
// T** as a dynamic array of pointers
class Student {
public:
    string name;
    Student(const string& n) : name(n) {}
};

int main() {
    int n = 3;

    // Allocate an array of n pointers
    Student** roster = new Student*[n];

    // Each pointer in the array points to its own heap object
    roster[0] = new Student("Ali");
    roster[1] = new Student("Sara");
    roster[2] = new Student("Hamza");

    // Access: dereference outer pointer to get Student*,
    // then -> to get member
    for (int i = 0; i < n; i++)
        cout << roster[i]->name << "\n";  // roster[i] is Student*

    // Cleanup: delete each inner object first, then outer array
    for (int i = 0; i < n; i++)
        delete roster[i];
    delete[] roster;
}
double_ptr_2d.cpp
// T** as a true 2D dynamic array (rows x cols)
int rows = 3, cols = 4;

// Step 1: allocate array of row-pointers
int** grid = new int*[rows];

// Step 2: allocate each row
for (int i = 0; i < rows; i++)
    grid[i] = new int[cols];

// Use like a normal 2D array
grid[1][2] = 99;
cout << grid[1][2] << "\n";  // 99

// Cleanup: delete each row first, then the pointer array
for (int i = 0; i < rows; i++)
    delete[] grid[i];
delete[] grid;
double_ptr_poly.cpp
// T** for polymorphic arrays — the most common OOP use case
class Person {
public:
    virtual void display() const = 0;
    virtual ~Person() {}
};
class Doctor  : public Person { public void display() const override { cout << "Doctor\n";  } };
class Patient : public Person { public void display() const override { cout << "Patient\n"; } };

void showAll(Person** arr, int n) {
    for (int i = 0; i < n; i++)
        arr[i]->display();   // virtual dispatch — correct override called
}

int main() {
    Person** staff = new Person*[2];
    staff[0] = new Doctor();
    staff[1] = new Patient();
    showAll(staff, 2);
    for (int i = 0; i < 2; i++) delete staff[i];
    delete[] staff;
}
⚠ Cleanup Order
Always delete the INNER objects first, then delete[] the outer pointer array. Reversing this order leaks every inner object.
03 Deep Copy Rule of Three
When a class holds a pointer to heap memory, the compiler-generated copy constructor and assignment operator only copy the pointer value (shallow copy) — both objects now share the same heap memory. Modifying or deleting one corrupts the other. A deep copy allocates new memory and copies the content.

The Rule of Three: if you define any one of (destructor, copy constructor, copy assignment operator), define all three.
✗ Shallow Copy (default — dangerous)
shallow.cpp
class Bad {
public:
    char* name;
    Bad(const char* n) {
        name = new char[strlen(n)+1];
        strcpy(name, n);
    }
    // NO custom copy ctor — compiler
    // generates: name = other.name;
    // Both objects share same memory!
    ~Bad() { delete[] name; } // double-free!
};

Bad a("Ali");
Bad b = a;         // shallow: b.name == a.name
// ~Bad() for b deletes memory
// ~Bad() for a → CRASH (double free)
✓ Deep Copy (correct)
deep.cpp
class Good {
public:
    char* name;
    Good(const char* n) {
        name = new char[strlen(n)+1];
        strcpy(name, n);
    }
    // Deep copy constructor
    Good(const Good& o) {
        name = new char[strlen(o.name)+1];
        strcpy(name, o.name); // NEW memory
    }
    // Deep copy assignment operator
    Good& operator=(const Good& o) {
        if (this == &o) return *this; // self-assign
        delete[] name;
        name = new char[strlen(o.name)+1];
        strcpy(name, o.name);
        return *this;
    }
    ~Good() { delete[] name; }
};
✓ Double Pointer Deep Copy
For T** (e.g. Medicine**), deep copy needs TWO levels: allocate a new outer array, then allocate new inner objects in a loop. Simply copying the outer pointer is shallow at the outer level; copying the outer array but not the inner objects is "half-deep" — still unsafe.
deep_copy_double_ptr.cpp
class Prescription {
    Medicine** meds;  // double pointer
    int count;
public:
    Prescription(int n) : count(n) {
        meds = new Medicine*[count];
        for (int i = 0; i < count; i++)
            meds[i] = new Medicine("Med" + to_string(i));
    }

    Prescription(const Prescription& o) {
        count = o.count;
        meds  = new Medicine*[count];      // new outer array
        for (int i = 0; i < count; i++)
            meds[i] = new Medicine(*o.meds[i]); // new inner objects
    }

    ~Prescription() {
        for (int i = 0; i < count; i++) delete meds[i];
        delete[] meds;
    }
};
04 Composition (has-a) strong ownership
Composition: the inner object is a direct member (not a pointer, not a reference). Its lifetime is fully controlled by the outer class — created when the outer object is created, destroyed when the outer object is destroyed. The inner object cannot exist without the outer object. Initialise via the initialiser list.
composition.cpp
class Clinic {
    string name;
    string location;
public:
    Clinic(string n, string l) : name(n), location(l) {
        cout << "Clinic '" << name << "' built\n";
    }
    ~Clinic() { cout << "Clinic '" << name << "' demolished\n"; }
    string getName() const { return name; }
};

class Doctor {
    string doctorName;
    Clinic clinic;           // direct member — composition
public:
    Doctor(string dn, string cn, string cl)
        : doctorName(dn), clinic(cn, cl) {} // Clinic init in initialiser list

    ~Doctor() { cout << "Doctor destroyed\n"; }
};

int main() {
    Doctor d("Dr. Ali", "City Clinic", "Karachi");
    // Output order:
    // Clinic 'City Clinic' built   (member init before body)
    // --- Doctor goes out of scope ---
    // Doctor destroyed             (destructor body first)
    // Clinic 'City Clinic' demolished  (then member destructor)
}
⚠ Constructor Order
Members are constructed in the ORDER they are declared in the class, not the order they appear in the initialiser list. Destructors run in REVERSE declaration order.
05 Aggregation by Pointer weak ownership
Aggregation: the outer class uses the inner object but does not own it. The inner object can exist independently and its lifetime is managed externally. With a pointer member, the outer class stores an address. When the outer object is destroyed, it does not delete the inner object — that would be overstepping ownership.
aggregation_pointer.cpp
class Department {
    string deptName;
public:
    Department(string n) : deptName(n) {}
    string getName() const { return deptName; }
    ~Department() { cout << "Dept destroyed\n"; }
};

class Employee {
    string empName;
    Department* dept;    // pointer — aggregation (does NOT own)
public:
    Employee(string n, Department* d) : empName(n), dept(d) {}
    // Destructor does NOT delete dept — we don't own it
    ~Employee() { cout << empName << " Employee destroyed\n"; }
    void display() const {
        cout << empName << " works in " << dept->getName() << "\n";
    }
};

int main() {
    Department* cs = new Department("Computer Science");
    {
        Employee e1("Ali",  cs);
        Employee e2("Sara", cs);   // SAME department, two employees
        e1.display();
        e2.display();
    }   // e1 and e2 destroyed — dept NOT deleted
    cout << "Department still alive: " << cs->getName() << "\n";
    delete cs;   // owner (main) deletes it
}

06 Aggregation by Reference T&
A reference member (T&) must be initialised in the initialiser list — references cannot be default-initialised or reassigned. Like pointer aggregation, the outer class does not own the referenced object. References cannot be null and cannot be reseated (changed to refer to a different object after construction).
aggregation_reference.cpp
class Engine {
    int horsepower;
public:
    Engine(int hp) : horsepower(hp) {}
    int getHP() const { return horsepower; }
};

class Car {
    string model;
    Engine& engine;   // reference member — aggregation
public:
    Car(string m, Engine& e) : model(m), engine(e) {}
    // MUST init in initialiser list — references can't be default-init
    void display() const {
        cout << model << " has " << engine.getHP() << "hp\n";
    }
    // No delete in destructor — we don't own the Engine
};

int main() {
    Engine v8(450);          // Engine exists independently
    Car c1("Mustang", v8);   // Car references v8
    Car c2("Camaro",  v8);   // Both cars share the same engine ref
    c1.display();
    c2.display();
    // v8 outlives c1 and c2 — correct
}
⚠ Dangling Reference
Never store a reference to a local variable that will go out of scope before the object holding the reference. The reference becomes dangling — accessing it is undefined behaviour.
07 Friend Functions friend
A friend function is declared inside a class with the friend keyword but is not a member of that class. It has access to all private and protected members of the class that befriended it. Commonly used for: operator overloading involving non-member functions, utility comparisons, and printing functions.
friend_function.cpp
class BankAccount {
    string owner;
    double balance;   // private
public:
    BankAccount(string o, double b) : owner(o), balance(b) {}

    // 1. Friend utility function — access private balance directly
    friend bool isRicher(BankAccount& a, BankAccount& b);

    // 2. Friend operator<< for printing (very common pattern)
    friend ostream& operator<<(ostream& os, const BankAccount& acc);
};

// Defined OUTSIDE the class — but has private access
bool isRicher(BankAccount& a, BankAccount& b) {
    return a.balance > b.balance;   // direct private access
}

ostream& operator<<(ostream& os, const BankAccount& acc) {
    os << acc.owner << ": Rs." << acc.balance;  // direct private access
    return os;
}

int main() {
    BankAccount a1("Ali",  50000);
    BankAccount a2("Sara", 80000);
    cout << a1 << "\n";                 // uses operator<<
    cout << a2 << "\n";
    cout << (isRicher(a2, a1) ? "Sara" : "Ali") << " is richer\n";
}
⚠ Friend ≠ Member
A friend function is NOT a member of the class. It has no this pointer. It takes the object as an explicit parameter. Friendship is not inherited — a derived class does NOT get the friend's access.
08 Friend Classes friend class
When you declare friend class Auditor inside Patient, every member function of Auditor can access all private/protected members of Patient. Useful for tightly-coupled helper/manager classes that need deep access without making everything public.
friend_class.cpp
class Auditor;   // forward declaration needed (used before definition)

class Patient {
    string name;
    double bill;
    string diagnosis;
public:
    Patient(string n, double b, string d)
        : name(n), bill(b), diagnosis(d) {}

    friend class Auditor;   // Auditor gets full access to Patient's privates
};

class Auditor {
public:
    void generateReport(const Patient& p) {
        // Direct access to private members — allowed because friend class
        cout << "--- AUDIT REPORT ---\n";
        cout << "Patient:   " << p.name      << "\n";   // private OK
        cout << "Diagnosis: " << p.diagnosis << "\n";   // private OK
        cout << "Bill:      Rs." << p.bill  << "\n";   // private OK
        cout << "Status:    " << (p.bill == 0 ? "PAID" : "UNPAID") << "\n";
    }

    void auditAll(Patient** patients, int n) {
        for (int i = 0; i < n; i++)
            generateReport(*patients[i]);
    }
};

int main() {
    Patient p1("Ali",  5000, "Fever");
    Patient p2("Sara", 0,    "Fracture");
    Auditor a;
    a.generateReport(p1);
    a.generateReport(p2);
}
⚠ Key Rules
Friendship is NOT symmetric: Patient befriending Auditor does NOT mean Auditor befriends Patient.
Friendship is NOT inherited: Auditor's subclasses do NOT get Patient's private access.
Always forward-declare the friend class if it hasn't been defined yet.
09 Templates & Generics template<typename T>
Templates let you write one piece of code that works for any type. The compiler generates a type-specific instantiation when it sees a call. Function templates work on any compatible type. Class templates create generic containers. Template specialisation overrides the generic version for a specific type.
function_template.cpp
// One function for ALL types
template<typename T>
T maxVal(T a, T b) {
    return (a > b) ? a : b;
}

// Two-type version
template<typename T, typename U>
void printPair(T a, U b) {
    cout << "(" << a << ", " << b << ")\n";
}

int main() {
    cout << maxVal(3, 7)          << "\n";  // int instantiation
    cout << maxVal(3.14, 2.71)   << "\n";  // double instantiation
    cout << maxVal('a', 'z')     << "\n";  // char instantiation
    printPair(42, "hello");              // T=int, U=const char*
}
class_template.cpp
template<typename T>
class MedVault {
    T* items[50];
    int count;
public:
    MedVault() : count(0) {}

    void add(T* item) {
        if (count < 50) items[count++] = item;
    }

    T* operator[](int i) const { return items[i]; }

    int size() const { return count; }

    ~MedVault() {
        for (int i = 0; i < count; i++) delete items[i];
    }
};

// Template with non-type parameter (compile-time constant size)
template<typename T, int MaxSize>
class FixedArray { T data[MaxSize]; ... };

int main() {
    MedVault<string> meds;   // T = string
    meds.add(new string("Panadol"));
    meds.add(new string("Brufen"));
    cout << *meds[0] << "\n";   // Panadol

    MedVault<Patient> patients;  // same template, different type
    patients.add(new Patient("Ali", 5000));
    patients[0]->display();
}
template_specialisation.cpp
// Generic template
template<typename T>
class Pair {
    T a, b;
public:
    Pair(T x, T y) : a(x), b(y) {}
    T sum() { return a + b; }
};

// Full specialisation for char — completely custom behaviour
template<>                     // empty template params
class Pair<char> {            // specialised for char
    char a, b;
public:
    Pair(char x, char y) : a(x), b(y) {}
    string sum() {            // returns string instead of char!
        string s = ""; s += a; s += b; return s;
    }
};

int main() {
    Pair<int>  pi(3, 4);
    Pair<char> pc('A', 'B');
    cout << pi.sum() << "\n";   // 7       (int version)
    cout << pc.sum() << "\n";   // AB      (char specialisation)
}
template_static_trap.cpp
// CRITICAL EXAM TRAP: static in template functions
template<typename T>
void counter(T val) {
    static int count = 0;   // separate static per instantiation!
    cout << "val=" << val << " count=" << count << "\n";
    count++;
}

int main() {
    counter(1);     // int: count=0 → prints 0, increments to 1
    counter(2);     // int: count=1 → prints 1, increments to 2
    counter(3.14);  // double: SEPARATE static, count=0 → prints 0
    counter(2.71);  // double: count=1 → prints 1
    counter(99);    // int: count=2 → prints 2
}
// Output:
// val=1   count=0
// val=2   count=1
// val=3.14 count=0    ← new static for double
// val=2.71 count=1
// val=99  count=2     ← resumes int's static
10 File Handling — Text Mode <fstream>
Use <fstream>. ofstream for writing, ifstream for reading, fstream for both. Always check if the file opened successfully with if (!file). Always close when done. Key modes: ios::out (write/create), ios::app (append), ios::in (read), combine with |.
file_write.cpp
#include <fstream>
#include <stdexcept>
using namespace std;

void savePatient(const string& name, double bill) {
    ofstream f("records.txt");           // creates/truncates
    if (!f) throw runtime_error("Cannot open file");
    f << name << " " << bill << "\n";
    f.close();
}

void saveMany(string names[], double bills[], int n) {
    ofstream f("records.txt");
    if (!f) throw runtime_error("Cannot open file");
    for (int i = 0; i < n; i++)
        f << names[i] << " " << bills[i] << "\n";
    f.close();
    cout << "Saved " << n << " records.\n";
}

// ios::app — opens without truncating, writes to end
void logError(const string& user, const string& msg) {
    ofstream log("error_log.txt", ios::app);   // APPEND mode
    if (!log) return;
    log << "[" << user << "]: " << msg << "\n";
    log.close();
}

// Analysis — read back and find user with most exceptions
void analyseLog() {
    ifstream log("error_log.txt");
    if (!log) { cout << "No log file\n"; return; }
    map<string, int> freq;
    string line;
    while (getline(log, line)) {
        if (line.empty()) continue;
        string user = line.substr(1, line.find("]") - 1);
        freq[user]++;
    }
    for (auto& p : freq)
        cout << p.first << ": " << p.second << " errors\n";
    log.close();
}

11 File Handling — Binary Mode ios::binary · read/write
Binary mode writes raw bytes — no newline translation, no text formatting. Use write() and read() with reinterpret_cast<char*>. Works on plain old data (POD) structs. Warning: do NOT binary-write objects with pointers — the pointer address will be saved, not the data it points to.
binary_file.cpp
#include <fstream>
using namespace std;

// Use fixed-size types — no pointers, no std::string
struct StudentRecord {
    char name[50];   // fixed-size char array, NOT string
    int  rollNo;
    float gpa;
};

void writeBinary() {
    StudentRecord s;
    strncpy(s.name, "Ali Ahmed", 50);
    s.rollNo = 1234;
    s.gpa    = 3.8f;

    ofstream f("students.dat", ios::binary);
    if (!f) { cerr << "Cannot open file\n"; return; }

    f.write(reinterpret_cast<char*>(&s), sizeof(s));
    f.close();
    cout << "Written: " << s.name << "\n";
}

void readBinary() {
    StudentRecord s;
    ifstream f("students.dat", ios::binary);
    if (!f) { cerr << "File not found\n"; return; }

    f.read(reinterpret_cast<char*>(&s), sizeof(s));
    cout << s.name << " | Roll: " << s.rollNo
         << " | GPA: " << s.gpa << "\n";
    f.close();
}

// Reading multiple records with seekg
void readRecord(int index) {
    ifstream f("students.dat", ios::binary);
    f.seekg(index * sizeof(StudentRecord), ios::beg);
    StudentRecord s;
    f.read(reinterpret_cast<char*>(&s), sizeof(s));
    cout << "Record " << index << ": " << s.name << "\n";
    f.close();
}

int main() {
    writeBinary();
    readBinary();
    readRecord(0);
}
⚠ Never Binary-Write Objects with Pointers or std::string
std::string contains an internal pointer. Binary-writing it saves the pointer ADDRESS, not the string data. When you read it back (different run, different memory layout), the pointer is garbage. Use char[] fixed arrays for binary file structs.
12 Exception Handling try · catch · throw
throw raises an exception. try wraps code that might throw. catch handles a specific type. Execution jumps from throw directly to the first matching catch — all code between is skipped. Catch by reference (&) to avoid slicing and allow polymorphism.
exception_basic.cpp
void divide(int a, int b) {
    if (b == 0) throw runtime_error("Division by zero");
    cout << a / b << "\n";
}

int main() {
    try {
        divide(10, 2);   // succeeds → prints 5
        divide(10, 0);   // throws — jumps to catch immediately
        divide(20, 4);   // NEVER reached
    }
    catch (runtime_error& e) {       // catch by reference
        cout << "Error: " << e.what() << "\n";
    }
    catch (int code) {                // catch by value (primitives)
        cout << "Code: " << code << "\n";
    }
    catch (...) {                      // catch-all — MUST be last
        cout << "Unknown exception\n";
    }
    // Program continues here after catch
    cout << "After try-catch\n";
}
custom_exception.cpp
// Inherit from std::exception and override what()
class HospitalException : public exception {
    string msg;
public:
    HospitalException(string m) : msg(m) {}
    const char* what() const noexcept override {
        return msg.c_str();
    }
};

void admitPatient(int beds) {
    if (beds <= 0)   throw HospitalException("No beds available");
    if (beds > 500)  throw runtime_error("Bed count overflow");
    cout << "Admitted. Beds left: " << beds - 1 << "\n";
}

int main() {
    try {
        admitPatient(5);
        admitPatient(0);    // throws HospitalException
    }
    catch (HospitalException& e) {
        cout << "Hospital: " << e.what() << "\n";
    }
    catch (runtime_error& e) {
        cout << "Runtime: " << e.what() << "\n";
    }
}
exception_hierarchy.cpp
// Exception hierarchy — catch derived before base
class AppException : public exception {
public:
    AppException(string m) : msg(m) {}
    const char* what() const noexcept override { return msg.c_str(); }
private: string msg;
};

class DatabaseException : public AppException {
public: DatabaseException(string m) : AppException(m) {}
};

class NetworkException  : public AppException {
public: NetworkException(string m)  : AppException(m) {}
};

void connect(int mode) {
    if (mode == 0) throw DatabaseException("DB timeout");
    if (mode == 1) throw NetworkException("No connection");
    if (mode == 2) throw AppException("Generic app error");
}

int main() {
    try { connect(0); }
    // MUST catch derived types BEFORE base types
    catch (DatabaseException& e) { cout << "DB: " << e.what(); }
    catch (NetworkException& e)  { cout << "Net: " << e.what(); }
    catch (AppException& e)      { cout << "App: " << e.what(); }
    catch (exception& e)         { cout << "Std: " << e.what(); }
    catch (...)                   { cout << "Unknown\n"; }
}
rethrow_stack_unwind.cpp
// Stack unwinding: when exception thrown, destructors of all
// local objects in scope run automatically (RAII guarantee)
class Guard {
public:
    Guard()  { cout << "Guard ON\n"; }
    ~Guard() { cout << "Guard OFF (stack unwind)\n"; }
};

void inner() {
    Guard g;          // constructor runs
    throw 42;         // exception! → ~Guard() auto-called
}

// Re-throw: pass the exception up the call stack
void middle() {
    try {
        inner();
    } catch (int& e) {
        cout << "Middle caught " << e << ", rethrowing\n";
        throw;   // re-throw current exception (no argument)
    }
}

int main() {
    try { middle(); }
    catch (int& e) { cout << "Main caught " << e << "\n"; }
}
// Output:
// Guard ON
// Guard OFF (stack unwind)   ← destructor called during throw
// Middle caught 42, rethrowing
// Main caught 42
⚠ catch(...) Must Be Last
catch(...) catches everything — if placed before specific catches, those specific catches become unreachable (the compiler may error or warn). Always order: most specific derived first → base class → catch-all last.

G1 Delegating Constructor — The Temporary Trap
delegating_ctor_trap.cpp
Point() { Point(1, 1); }   // THIS IS WRONG
// This does NOT call Point(1,1) on *this
// It creates a TEMPORARY Point(1,1) object, then discards it
// *this remains uninitialised

// Correct C++11 delegation:
Point() : Point(1, 1) {}    // ← in the initialiser list

// Exam consequence: Point() { Point(1,1); }
// means the Point(int,int) ctor DOES run (and prints output)
// but only for the temporary — the actual object is unset

G3 Copy Constructor vs Assignment Operator
copy_vs_assign.cpp
MyClass a;
MyClass b = a;   // copy constructor  (initialisation)
MyClass c(a);    // copy constructor  (same thing)

MyClass d;
d = a;           // assignment operator (d already exists)

// Rule: if the object is being CREATED in the same statement,
// it's ALWAYS the copy constructor, never operator=

// Inside a function parameter:
void foo(MyClass x) { ... }   // x created by copy constructor
foo(a);                        // copy ctor called, NOT operator=
G4 Virtual Destructor — Why It Matters
virtual_destructor.cpp
class Base {
public:
    ~Base() { cout << "~Base\n"; }   // NOT virtual — dangerous
};
class Derived : public Base {
public:
    ~Derived() { cout << "~Derived\n"; }
};

Base* p = new Derived();
delete p;
// Output: ~Base   ONLY — ~Derived never called → memory leak!

// Fix: make base destructor virtual
virtual ~Base() { cout << "~Base\n"; }
// Now delete p → ~Derived then ~Base  ✓
G5 catch(...) Placement — Order Matters
✗ Wrong order — error
try { throw 'x'; }
catch (int e)  { ... }
catch (...) { ... }   // ✓
catch (char e) { ... } // ✗ UNREACHABLE
// catch(...) already catches everything
// catch(char) after it is an error
✓ Correct order
try { throw 'x'; }
catch (int e)  { ... }  // specific
catch (char e) { ... }  // specific
catch (exception& e) { ... } // base
catch (...) { ... }   // catch-all LAST
G6 Member Initialisation Order — Declaration, Not List
init_order_trap.cpp
class Trap {
    int b;   // declared first
    int a;   // declared second
public:
    Trap() : a(10), b(a) {}   // LOOKS like b=a=10, but...
    // Members are initialised in DECLARATION order: b first, then a
    // So b = a (a is uninitialised at this point!) → undefined!
    // a = 10  (correctly set)
};

// Fix: reorder the declarations to match intended init order
class Fixed {
    int a;   // declared first → initialised first
    int b;   // declared second
public:
    Fixed() : a(10), b(a) {}   // now a=10, then b=a=10 ✓
};
